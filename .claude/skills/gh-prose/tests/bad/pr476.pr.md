**What was decided that the design did not cover**
- **The new rows carry no `category`.** The issue says to keep `category` as history, and these rows never had one. Giving them a category would also change the old-category count table that doc 01 states and the test parses, and doc 01 is outside this file set. So `counts_by` skips rows without the field, and the crosstab prints them under `-`.
- **`mechanism_why` is empty on 132 rows.** On these rows the mechanism is the one the old category named (A K1, B K5, C1 K8, C2 K7, ignore K9), so `why` already covers it. The test requires `mechanism_why` everywhere else: every row whose mechanism departs from its category, both formerly undecided rows, and all eight new rows. This is exactly the rule `classify.py` generated (80 rows have a reason; 75 of them depart from their category).
- **`mechanism_why` is English.** The mapping's `mechanism_why` text is Chinese. It was translated one group at a time (32 distinct strings), and the design-doc references in it (§4.14, D72, §4.12, §9) were dropped.
- **The consistency rules had to use fields that exist.** The issue's examples assume a cross-LP peer field and bound fields, and the inventory has neither. `peer` names a thread, process or deployment, not an LP. So the test checks what `peer` can refute and reads a bound from the row's shape and expression. The four rules:

  | Mechanism | Rule |
  |---|---|
  | K5 | `peer` ∈ {process, deployment} |
  | K6 | `peer` ≠ deployment |
  | K7 | the row is an anchor, a sleep, or has a `timeout` in its expression |
  | any | `mechanism_why` is set wherever the mechanism departs from the category |

  Two of the issue's examples cannot be stated with these fields:
  - **"K6 rows do not have a cross-LP peer."** 31 K6 rows have `peer: process`, because the tensor-parallel workers and the frontend's engine are other processes inside the same LP. Only `deployment` refutes K6.
  - **"K8 rows carry a bound."** The design itself classes `async_proc.py:482` (`multiprocessing.connection.wait(sentinels)`, process-death detection, no timeout) as K8. So the bound rule applies to K7 only.

  Adding a real `lp` or `bound` field would mean 220 more judgements that the mapping does not supply. That is left for a later issue if a consumer needs it.

**What surprised me**
- The identical-call conflict. It is the one thing the design's (file, line)-keyed generator could not see.
- The mapping's reason text was Chinese, which cannot go into a GitHub artifact as written.

**What was left undone**

The `#53 category` crosswalk's `Count` column stays valid, because the new rows have no category. I noted this on #450.

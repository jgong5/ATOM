## Both static passes name their own blind spots and both lists are short

`atom/compass/detect/set_iteration.py` and `atom/compass/detect/clock_source.py`
each say that finding a read takes two recognitions — the expression has to be
recognised as a set (or as a clock), and the thing done to it has to be
recognised as a read — and each carries a written list of what it does not
find. Round 2's review of #96 invented 38 forms against the set pass and 22
against the clock pass, and found five things that are missed with nothing on
either list saying so.

None of these is a false positive; every one is a miss, and every one is an
**addition** — a name in a constant, or a recogniser. #96 was at 1.00x AST
against the 200–300 band before its round-3 fixes and is at 1.09x after them,
so the review's condition was that its two false positives (both subtractions)
land there and that everything below lands here instead. This is that issue.

Everything below is measured on `ee5b591dc` — #96's round-3 head, with both of
those subtractions in — rather than read off the lists.

---

### 1. `print(s)` is the same expression as `str(s)`, and the list has one of them

The comment above `ORDERED_READS` says `str`, `repr` and `format` are in the
tuple *"because a set's `repr` lists its members in the order it holds them"*.
`print` calls `str`. It is the commonest way a set's repr reaches an output
stream, and it is not reported:

```
print                        -> []
log-deferred-%s              -> []          # log.info("ready=%s", s)
str-is-reported              -> ['engine.py:3  str() over s  in f']
percent-binop-is-reported    -> ['engine.py:3  formatted string of s  in f']
```

The `%` `BinOp` spelling **is** caught, including the tuple form, so the
deferred-interpolation spelling of the identical string is the one that gets
through. This is the set pass's own argument — *"`s - t` and `s.difference(t)`
are one expression written two ways, so recognising one and not the other would
be two rules where the language has one"*, the argument it uses for
`SET_METHODS` and for the sleep pair in #101 — applied to itself.

### 2. Reads that carry hash order into something that then looks ordered

`out.extend(s)` is the sharpest of these: it is a read that puts the set's hash
order straight into a list, which is ordered from that point on and no longer
looks like a set. That is the same argument `fromkeys` is in the tuple on.

```
list.extend                  -> []
deque                        -> []          # collections.deque(s)
Counter                      -> []
islice                       -> []          # itertools.islice(s, 2)
np.fromiter                  -> []
```

`extend` is also the one that needs a receiver type rather than a name: so does
`Event.wait` in #101, and it is the same design question in the same two
modules.

### 3. `<Class>.<name>` — round 1's Finding 4 named two spellings and one is open

Round 1 of #96 wrote: *"A plain class attribute has the same shape:
`members = {"a", "b"}` binds `members`, and `Step.members` / `self.members` are
not flagged."* Round 2 closed the `self.` half. `_declared` writes `members` and
`self.members`; nothing writes `A.members`, and `_owner` only routes the `self.`
prefix.

```
class-name-outside           -> []          # def f(): for x in A.members
class-name-inside            -> []          # A.members read from a method of A
self-name-is-reported        -> ['engine.py:5  for-loop over self.members  in f']
```

#96's round 3 added `Step.members` to the not-found list, which is the cheaper
of the two things the review asked for. Resolving `<ClassName>.<name>` the way
`self.<name>` now resolves is the other, and it belongs here.

### 4. Bindings that are misses rather than shadows

```
global-no-module-binding     -> []          # `global ready; ready = set(n)`, read from another function
nonlocal                     -> []
paired-unpacking             -> []          # a, b = set(x), set(y)
augmented-only               -> []          # s |= set(b) with no other binding
```

A `global` or `nonlocal` declaration says which scope the following binding
writes to, and `_binds` records the binding in the scope the statement is
written in. `a, b = set(x), set(y)` is the positive half of the unpacking that
#96's round 3 just made a *stated* unclaim: the elements of a `Tuple` value
line up one-for-one with the elements of a `Tuple` target, so this is the one
unpacking whose names can be claimed.

### 5. `CLOCK_READS` is missing five real clocks and says nothing about it

The clock pass's blind-spot list is entirely about the *parser*: `from time
import *`, `importlib.import_module("time").monotonic()`, a clock on a class
attribute, a clock in a parameter default. That half is accurate — round 2
could not break it. But the pass's second recognition is `CLOCK_READS` itself,
and nothing in the module states whether that constant is complete.

```
process_time                 -> []
process_time_ns              -> []
thread_time                  -> []
thread_time_ns               -> []
datetime.today               -> []
monotonic-is-reported        -> ['engine.py:5  time.monotonic  in f']
```

All five are real machine clocks, in the same two modules as the listed ones.
None of the five appears anywhere in `atom/` today, so this is a list to close
rather than a bug to fix — but the fix is to give the constant the same
two-sided statement the set lint's docstring now has, not to add five names
quietly. (`loop.time()` is the receiver-typing class and belongs to #101.)

### What the work is

* Decide each of the five against the same standard the existing entries were
  decided against, and write the reason beside the entry the way the existing
  ones are written. A name added with no line saying why is what produced this
  issue.
* `extend`, `deque`, `Counter` and `<Class>.<name>` need the receiver or the
  qualifier typed, which `_resolve` and `_declared` do not do today. That is
  the same design question #101 raises for `Event.wait` and `Queue.get`, in the
  same two modules, and the two issues should be decided together rather than
  each inventing its own answer.
* `print` and `log.info("%s", s)` are the cheapest and the most valuable: one
  tuple entry and one call-shape, and between them they cover the way a set's
  repr usually escapes.
* Every form above is a probe already written. `tests/compass/clock/test_static_checks.py`
  holds `FORMS_THAT_FIRE` and `FORMS_THAT_STAY_QUIET` as the regression set; a
  form that moves from one dict to the other is how this work should be landed.

### Where it does not belong

Not in #96. Its round-2 review measured it at 1.00x AST and 2.07x physical
against the 200–300 band and attached the condition explicitly: *"a PR sitting
at 1.00x AST cannot absorb another recogniser without the halt becoming a real
one."* Round 3 landed the two subtractions it asked for and is at 1.09x AST.

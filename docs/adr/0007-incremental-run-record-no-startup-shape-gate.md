# 运行记录增量落盘，不设启动期形状闸门

[ADR-0001](0001-table-residual-forward-clock-boundary.md) 规定运行期估时拒绝即终止本次仿真，理由是 `schedule()` 已经改变请求与 KV 状态、不可回滚。它的代价是长时间运行可能在后段失败，而已完成的工作随之丢失。曾考虑在启动期按 ATOM 配置的 `max_num_seqs`、`max_num_batched_tokens`、`max_model_len` 推出形状包络，对校准包的覆盖范围预先核对并拒绝。

这个方案被否决：这三个值是调度器能够产生的上界，不是运行中会出现的值。实际 batch size 由到达率与 KV 容量决定，是仿真的输出而非输入，启动前无法算出。按上界设闸只能给出"可能超界"，会在大量实际不会超界的运行上报警，最终被忽略。

改为让失败变便宜：逐 step 运行记录增量落盘，默认 `summary` 级别，可选 `full`。逐 step 记录本就是设计要求——来源记录、受影响 step 与预测秒数的比例统计（明确不得由累计计数相减得出）、以及 `measured` 模式的 CPU 样本都需要它——此处决定的只是写出时机。拒绝发生时强制 flush 后再走终止路径，使终止前的记录不留在缓冲区里。

序列化与写盘属于仿真运行开销，必须在 CPU 实测的测时窗口之外执行，否则会把日志开销计入目标 CPU 耗时。其成本远低于被记录的估时本身，不构成性能理由。同时不实现启动期的形状阶梯试算报告：它只输出信息、不改控制流，价值不足以进入首版。

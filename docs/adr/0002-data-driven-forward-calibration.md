# 模型和并行配置的变化通过目标配置与校准包表达

`TableResidualBackend` 使用固定的推断实现；在已经支持的执行契约内，更换模型、并行度或校准目标只改变目标配置与校准包。校准包包含测量表、网格、可选形状修正、特征定义及其尺度、回归器参数、融合权重和适用性证据；缺少匹配校准包时明确拒绝，不重用其他目标的参数。

这要求首版就将目标相关常量、资产路径和特征选择从原实验实现中抽成数据，并提供统一的拟合／导出输入契约。初期工作量高于直接包装固定目标的预测器，但能避免以后每增加一个模型或 TP/DCP 配置就修改代码；原预测器与资产可作为方法参考及可选导入来源，不要求复制历史运行环境或复现冻结输出。

实际执行参数只有一个来源：EngineCore 收到的、已经完成规范化与部署改写的 ATOM 配置。Compass 装配层从中提取不可变的纯值快照，在构造后端时注入；每步的 `estimate(BatchView)` 接口保持不变。后端不自行读取 native Config，成本配置也不重复填写可覆盖 ATOM 的 TP/DCP。校准包的适用条件用于核对这份快照。

修正项是否使用同时取决于实际执行条件与校准配方。顶层 `decode_context_parallel_size == 1` 时，不需要 DCP 修正及专用特征，也不要求 DCP 系数；DCP 启用时，匹配配方仍可以选择直接拟合而不单列 DCP 修正。修正系数、特征定义、残差模型及融合权重通过配置文件和引用的制品提供。跳过一项不能使原有 DCP8 的基线与残差参数自动适用于无 DCP 目标，需要适用条件、特征与参数契约一致的组合。

残差融合同样可以由配置关闭。`corrections: []` 与 `ensemble: null` 表达基础查表／恢复模式，直接返回基线结果，不加载增强模型；选择融合模式时再提供相应参数。基础模式保留表内部的校准恢复，并按实际路径记录来源。测量表已经包含其原执行配置的物理耗时，关闭额外 DCP 修正不等于改变 DCP 并行度。

调度预算与特征归一化单位分别管理，不能修改前者时顺带改变后者。校准包不携带新的 Python 插件或任意执行表达式；新增执行模式、特征算法或并行拓扑能力属于实现扩展。配置感知不扩大首版一个 engine、DP1/PP1/PCP1、一次完整 forward 计价的闭环范围。

运行所需参数和已知兼容性必须检查；历史精度／capture 等证据不足时记录未知状态，首版不以补齐 GPU 精度报告为加载或验收前提。通过输入切换的功能测试也不构成新目标的精度证据。

# 校准条件按证据强度分四级校验

目标配置与校准包的核对涉及两类条件：进入特征计算的值（block、DCP、chunk budget、interleave、CU 数），以及不进入特征但构成测量表成立前提的值（TP、KV dtype、graph 模式）。两类的失配后果相同——表里每个数都不再适用——但只有前者是模型的输入。按"是否是特征"单一判据分类会把 TP 这类条件降级成警告，而 TP8 的包配 TP4 运行必须拒绝。

因此按失配后果与证据可得性分四级。A1 为包内声明、不匹配即拒绝，涵盖上述两类条件以及测量表摘要、网格参数和配方的 `code_digest`。A2 为校准包拿不出证据、由用户在运行输入的 `asserted_calibration_conditions` 中手写断言的条件：未断言即拒绝，断言后放行并记为未验证。B 为只记录、不拦截的条件，如 DCP 通信选项与 KV dtype 的细格式。C 为由 A1 算出的派生量，如分块宽度，不单独声明，只进 provenance。

A2 只有三个成员：权重量化配置、完整 graph ladder、prefill logits 选择口径，正是设计文档中标为"未证实"的三项。它存在的理由是把一个本来藏在默认值里的假设搬到文件里：用户亲手写下该值并附来源，这个动作本身进入证据链。降级到 B 会让 BF16 权重配 MXFP4 的表静默跑完；升级到 A1 则首个校准包直接无法加载。

断言写在运行输入而非校准包内。[ADR-0002](0002-data-driven-forward-calibration.md) 已禁止通过修改包内标签通过检查；校准包是不可变证据，用户可改的内容不放进去。断言的语义是对测量历史的声称，不是对本次执行的配置：校验比较的是断言值与 ATOM 已解析配置是否一致。

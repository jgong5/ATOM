# P0.2 — Baselines before the first Compass commit

Status: **complete**. Ends in an escalation: gate 1 as written in `16` D98 cannot
be met on any container available to us.

## Brief

Record ATOM's test-suite and lint state at the commit Compass development
branches from, so that every later task's gate 1 ("ATOM's 187-file test suite
passes **unmodified**") has a reference to compare against. Pure measurement,
no edits to ATOM. Named result stated in advance: *the pass/fail counts and the
ruff error count at `83daf636d`.*

### Result 1 — suite, GPU container, `tests/plugin` excluded

```
python -m pytest tests/ --ignore=tests/plugin -q --no-header -p no:cacheprovider -rf
5 failed, 4730 passed, 105 skipped, 3 xfailed, 18 warnings in 137.76s
PYTEST_RC=1
```

The five failures, all pre-existing and all bf16 numeric tolerance on this
hardware — none is a logic failure and none is reachable from CPU-only code:

| Test | Assertion |
|---|---|
| `tests/test_dcp_merge_ops.py::test_row_view_matches_output_slicing_bitwise` | `torch.equal` on bf16 — differs in the last mantissa bit (`0.0447` vs `0.0449`) |
| `test_fused_compress_ragged.py::...[extend0-context0-cut+whole]` | `max|diff|=0.001953125` vs `atol=rtol=1e-3` |
| `...[extend1-context1-whole+cut]` | same, `0.001953125` |
| `...[extend2-context2-resume+fresh]` | same, `0.001953125` |
| `...[extend4-context4-tiny-then-long]` | same, `0.001953125` |

`0.001953125` is exactly 2^-9 — one bf16 ULP at these magnitudes. The two files
compare a fused kernel against a reference at a tolerance tighter than bf16
rounding, so the failures look like a tolerance/hardware mismatch rather than a
regression. **Not investigated** — outside P0.2's scope, flagged for the owner.

## Escalation — three items for the owner

**1. Gate 1 is not satisfiable as written.** `16` D98 gate 1, `08` D43.1 and
ATOM's own `CLAUDE.md` ("all tests (no GPU needed — mocks AITER and
torch.cuda)") all assert the suite runs GPU-free. Measured, it does not: 28 of
187 test files import a path that shells out to `rocminfo` at collection time.
And no single container can run the suite *and* the linters. Options:

  - **(a)** Restate gate 1 as a *delta* gate: "no test that passed at
    `83daf636d` fails after this change", run in the GPU container with
    `--ignore=tests/plugin`, against the 4730/5 baseline above. Lint runs
    separately in the CPU container. Cheapest; accepts a GPU dependency on
    every task's gate.
  - **(b)** Define a CPU-collectable subset (the 150 files that do collect) and
    make *that* gate 1, with the GPU superset run once per wave. Keeps most
    tasks hardware-free, which is what `16` D101 wants.
  - **(c)** Fix the container: install ruff/black in the GPU image, or get
    `rocminfo` mocked at collection in the CPU image. Real work, unknown size,
    touches ATOM or the image rather than Compass.

  Recommendation: **(b)**, with (a) as the wave-level check. It preserves the
  "GPU is scarce" premise; (a) alone would put a GPU booking in front of every
  single task's gate.

**2. Five pre-existing failures.** Whatever gate 1 becomes, it must be a delta
against these five, not "green". They are bf16 ULP failures in
`test_dcp_merge_ops.py` and `test_fused_compress_ragged.py`; a Compass change
cannot plausibly touch them, so they are noise — but a reviewer reading "5
failed" cold will read it as a regression. The baseline must be cited in every
review record.

**3. Node 39 is unusable.** 2,183+ D-state processes, `rocminfo` never returns,
and `timeout` cannot kill a process in uninterruptible sleep. ATOM's *own*
import hangs there because aiter's arch discovery touches the driver — which
means the "CPU-only, no hardware" tasks in `16` are only hardware-free on a
node whose driver is healthy. All Phase 0 execution moved to node 18. This
bears on P0.1: the pre-flight script must run before *any* task, not only GPU
tasks.
